# soroban 插件

soroban 扫本目录下的 `soroban-plugin-*`（各含 `plugin.toml`）作为插件。
插件是**独立仓库、独立环境**，soroban 不跟踪其代码，只按清单调它的标准 CLI。

**插件不等于爬虫**。淘宝订单抓取只是第一个；汇率、国际快递查询都没有「爬」的语义。
所以目录、前缀、术语一律叫 plugin。（旧的 `scraper/soroban-scraper-*` 仍会被扫描，
是为了老部署升级后插件不至于凭空消失，不是长期形态。）

## 现有插件

| 目录 | 干什么 | 要装吗 |
|---|---|---|
| `soroban-plugin-taobao` | 抓淘宝/闲鱼订单 → 暂存表 | 要（Playwright + Chromium，约 400MB） |
| `soroban-plugin-fx` | 取汇率 → 账本 | **不用装**（只依赖 httpx，跑 soroban 自己的解释器） |

## ⚠️ 把插件发给别人之前

插件目录里有**你自己的凭据**，`.gitignore` 管不着分发（分发是文件拷贝，与 git 无关）：

| 要删掉 | 是什么 |
|---|---|
| `.state/*.json` | 你的**浏览器登录会话**（淘宝 cookie）。拿到它的人就是你 |
| `.env` | 你的 soroban 账号密码 / API key |
| `*.log` | 抓取日志，含订单号、账号昵称 |
| `.venv/` | 机器相关，拷过去也跑不了，纯占几百 MB |

`pyinstaller.bat` 打包时会检测这些实物并醒目提示，但**它不会替你删**
——删错了没法撤销，这一步必须是你自己按的。

## 什么该做成插件，什么该留在核心

**判据先于形态。** 这套机制只有一种形态——「fire-and-forget 子进程 + 一次性令牌 +
HTTP 回灌」——而它的隐含前提是：任务是批量异步的、可以慢、结果一行 JSON 就说得清、
每次调用付得起「起进程 + 加载依赖」的代价。

按这个前提划线：

| | 做成插件 | 留在核心 |
|---|---|---|
| 要不要外部网络/凭据/浏览器 | 要 | 不要 |
| 失败是不是常态（风控、改版、断网） | 是 | 否 |
| 能不能异步、能不能慢 | 能 | **不能**（用户在等一个 HTTP 响应） |
| 有没有重量级常驻状态（模型、连接池） | 没有 | 有 |
| 核心愿不愿意背它的依赖 | 不愿意 | 愿意（已经背了） |

照这张表：汇率 → 插件、订单爬虫 → 插件、快递物流查询 → 插件、**截图 OCR → 核心**。

### OCR 为什么不是插件

它是唯一一个「前四条全部踩反」的能力：用户拖了张图正在等（同步）、RapidOCR 的模型
加载是秒级且必须常驻（重量级状态）、不碰任何外部凭据、失败不是常态。
做成子进程意味着**每张图重载一次模型**。

代价是诚实的：核心因此背着 rapidocr + pillow + onnxruntime，这是打包体积的大头。
接受这个代价，好过为一个能力凭空造出第二种插件形态（长驻进程 + 双向 RPC + 进程探活
+ 非一次性令牌），把整套机制的复杂度翻倍。

**什么时候才该造第二种形态**：出现**第二个**同类候选时（比如「多种 OCR 引擎可选」、
本地大模型打标）。一个候选不足以支撑一套新抽象——那是过早泛化。

## 两条通道，仅此两条

```
核心 → 插件    子进程 CLI。令牌走 SOROBAN_TOKEN、配置走 SOROBAN_CONFIG，
               都不进 argv（进程表 ps 与日志里看得见 argv）。
插件 → 核心    HTTP，带**限权**令牌。要么用现成的 REST（如淘宝插件写 /api/staging），
               要么用通用写入通道 POST /api/plugins/ingest。
```

**加一种新数据不需要新开接口**：写一个 handler 并 `@register(...)`（见
`backend/app/services/ingest/kinds/`），插件发 `{"kind": "...", "items": [...]}` 即可。
需要自己存点东西（轨迹去重、上次轮询时间）用 `kind = "plugin.record"`，按插件隔离命名空间。

## 权限：默认全拒

清单里 `scopes = [...]` 声明要什么，**用户在插件页勾选后才真正生效**。
实际拿到的是「清单声明 ∩ 用户授权 ∩ 核心已知」的交集，任务结束令牌立即作废。

三重交集各挡一件事：多勾没用（插件自己没声明）、插件升级偷偷加一项不生效（卡片标
「需要新授权」，`git pull` 不该悄悄扩权）、核心删掉某个权限后旧授权自动失效。

### 这套东西防的不是恶意插件

插件是本机子进程、代码你自己能改——拿到令牌就能干令牌能干的事。它防的是：

1. **误伤**：插件里一个写错的 URL 把 DELETE 发到了 `/api/orders/1`；
2. **静默扩权**：更新插件后它多要了一项权限，没人察觉；
3. **说不清**：出问题时无法回答「那一轮插件到底动了什么」。

对你可见的价值只有一句：卡片上写着「本插件只能写暂存，不能直接进账本」，**而这句话是真的**。
真话的前提是权限挂在**路由**上而不是路径前缀上——`POST /api/staging/{id}/import` 在
`/api/staging` 前缀下，干的却是「直接建正式账本单」。

## 写一个插件

```toml
id = "myplugin"
name = "我的插件"
version = "0.1.0"

python = "inherit"          # 依赖已在 soroban 里 → 不建 venv、不用安装
# python = ".venv/bin/python"   # 有重依赖就走独立环境

entry = "-m my_plugin"      # 标准 CLI
scopes = ["fx:write"]       # 要什么权限（用户在卡片上勾选后才生效）
settings = ["fx.stale_hours"]  # 要读核心的哪几项设置（**跨插件通用的偏好**才放核心；
                               # 只有本插件懂的用下面的 [[params]]）

# 按账号展开成多个子进程；不写 = 整体跑一次（汇率、快递查询这类）
# accounts = true
# accounts_ledger_field = "platform_account"   # 账号名落到账本哪一列（才支持按账号改名/删单）

# 能执行什么。**卡片上的按钮就是按这些长出来的**，核心不认识任何具体动词。
[[commands]]
name = "fetch"              # 传给你 CLI 的动词
label = "抓取"              # 按钮上的字
hint = "鼠标悬停时的说明"
primary = true              # 主按钮（高亮那个）
needs = ["fx:write"]        # 缺权限就禁用按钮并说明，而不是点了收 403
# per = "account"           # 每个账号起一个进程；默认 plugin = 整体一次
# confirm = "确定要清空吗？"  # 非空则先弹确认

# 插件私有参数。**卡片上的表单就是按这些长出来的**，核心不理解其含义，
# 只负责存、校验类型、渲染控件、下发（运行时在 SOROBAN_CONFIG 的 params 里）。
[[params]]
key = "timeout"
label = "超时（秒）"
type = "int"                # bool | int | str | select | secret
default = 20
min = 5
max = 120
hint = "?" 号里的说明
```

**跨插件通用的偏好放核心**（`services/prefs.SPECS`，设置页统一渲染），插件用 `settings = [...]`
声明要读哪几项；**只有本插件懂的**放 `[[params]]`。分不清就问一句：换个插件还成立吗？

`secret` 类型的参数存下来但**不回显**（API 只回「已设置/未设置」），日志里也会脱敏。

CLI 约定：**stdout 只吐一行 JSON**（soroban 解析它写日志），日志走 stderr，
有失败就非零退出——否则「30 单全被拒」和「一切正常」在界面上长得一模一样。

## 核心保证什么、限制什么

上面那些是你能**声明**的。这一节是反过来的：核心在运行时替你保证了什么、
又会拿什么约束你。不写清楚的话，插件作者只能靠猜，最常见的结果是把核心已经做了的事
再做一遍（多一把锁），或者以为核心会做而其实不会（令牌的生命周期）。

**保证**

- **一个账号同时只会有一个子进程。** 互斥键按「插件 + 账号」算，**跨命令**——
  `fetch [甲]` 跑着的时候 `login [甲]` 会被挡下（反之亦然），因为它们抢的是同一份
  登录会话文件。所以插件**不需要**自己再加账号锁；加了也只是重复。
  不同账号之间、以及不按账号跑的命令之间，互不相干。
- **一个子进程一枚令牌**（`SOROBAN_TOKEN`），进程退出即作废。多账号扇出时每个账号
  各拿各的——别把令牌存到磁盘上跨进程复用，下次跑必然 401。
- **拒收会被核心自己记一笔。** 你往 `/api/ingest` 推的东西被拒了多少条、第一条为什么，
  核心记在自己这边并显示在卡片上，**你自报的成功盖不掉它**。
  所以不必为了「让界面好看」去吞掉错误——吞了反而对不上。
- 权限**默认拒绝**：清单里多写一项 `scopes` 不会自动生效，用户要在卡片上勾。
  升级插件不会悄悄扩大权限面。

**限制**

- **单次执行最长 30 分钟**，超时后核心会连你拉起的孙进程一起按进程组回收
  （所以别用 `setsid` 把浏览器甩出去，那样回收不到）。
- 输出**只保留末尾若干 KB**：话多的插件（playwright 的 debug 日志能到上百 MB）
  不会把后端内存吃掉，但也意味着开头的日志会丢——要紧的信息写在结尾。
- 结果 JSON 只认「最后一行」。中途 print 的东西不会被当成结果。
- `state_dir` 下的文件名就是账号名，核心会按它判断「这个账号授权过没有」，
  也会在改名/删号时一起迁移。别在那个目录里放账号会话之外的东西。

## 结果那一行 JSON：核心认识哪些键

插件跑完之后，**stdout 的最后一行**要是一个 JSON 对象；核心据此在卡片上写一句人话
（实现见 `backend/app/routers/plugins.py` 的 `_summarize`）。这是一份真实的契约，
以前只存在于代码里，现在写下来。

**计数键**（值为 0 时不显示；顺序即显示顺序）：

| 键 | 卡片上显示成 |
|---|---|
| `created` | 新建 N |
| `updated` | 更新 N |
| `unchanged` | 无变化 N |
| `skipped` | 跳过 N |
| `blocked` | 挡下 N |
| `failed` | 失败 N |
| `rejected` | 拒收 N |

**其它认识的键**：

- `error` —— **非空时压过一切**，整句就是它。注意：它与退出码是**两个独立的信号**，
  核心两个都看。退出码 0 且带 `error` ⇒ 卡片是黄色的「warn」，不是绿色的成功。
- `logged_in` —— 真值时显示「登录成功」。
- `rate` / `source` —— 显示成「1元 = X円（源）」。
- `ok` / `account` —— **核心会读，但不显示**。`account` 尤其注意：账号名已经由核心拼在
  整句最前面了，你再吐一遍不会重复显示（但也不要指望它显示）。

**核心不认识的键**：值是**非空字符串**的，会原样接在末尾（多个用「；」分隔，总长截到 120 字）。
布尔、数字、列表**一律跳过**——它们对用户没有意义，显示 `pushed=True`、`tried=['boc']`
这种 Python 字面量只会让卡片变难读。所以：**想让用户看见的话，写成一个字符串键**，
例如 `{"note": "没有 SOROBAN_TOKEN，只取不交"}`。

**三种特殊情形**：

- 计数键**出现了但全是 0** ⇒ 显示「本轮无变化」。这是定时抓取最常见的结局，
  所以哪怕这一轮什么都没做，也**请把计数键带上**（`{"created": 0, "updated": 0}`），
  否则核心分不清「跑完了没东西」和「你什么都没说」。
- 一个计数键都没有、且没有核心不认识的键 ⇒ 显示「已完成」。
- 那一行**解析不出 JSON** ⇒ 原样显示（截到 200 字）。所以调试信息请走 stderr：
  stdout 是结果通道，最后一行被别的东西占了，卡片上就会出现一句无关的话。

⚠️ 核心**只看最后一行**。如果你在结果之后还往 stdout 写了什么（库的告警、`print` 调试、
Windows 上的编码提示），那一行就会被当成结果。日志一律走 stderr。
